# Solo VPS v0.2.3 — Coolify 4.4.6 maintenance alpha

This patch qualifies **Coolify 4.4.3 → 4.4.6**. Traefik remains on reviewed **3.7.14**, Sentinel on **1.0.2**. Solo VPS remains an alpha for one Ubuntu 24.04 application VPS.

## Update

Prepare a new `v0.2.3` checkout with the existing external config, inventory and keys. Keep the previous checkout and fresh verified off-host backups. Follow [How to update](https://paracosm17.github.io/solo-vps/operations/updates/) ([русский](https://paracosm17.github.io/solo-vps/ru/operations/updates/)).

Pause deployments and settings/ENV changes. Run `make coolify-upgrade-preflight` with the exact configured Sentinel HTTPS URL, then the explicitly confirmed `make coolify-upgrade`. Finish with `make verify`, `make audit`, application HTTPS checks and Sentinel delivery. Older installations must follow intermediate release notes until Coolify 4.4.3 is installed. No proxy, Docker or application upgrade is required for an installation already on v0.2.2.

## Changes

All official 4.4.4, 4.4.5 and 4.4.6 notes and the exact tag comparison were reviewed. The direct transition includes upstream fixes for IPv6 URLs/servers, database and Compose configuration, DNS/backup handling, cleanup and duplicate update jobs. 4.4.5 removes the short-lived 5 GB free-space upgrade restriction; 4.4.6 fixes PHP startup compatibility by pinning the compatible base image. Installation artifacts, embedded Reverb and Sentinel remain unchanged.

**Three forward-only database migrations** normalize IPv6 server addresses/Sentinel URLs and remove duplicate `REDIS_USERNAME` and `NIXPACKS_NODE_VERSION` records. Redis duplicates are grouped per resource; Node-version duplicates are grouped per resource and preview flag. The newest timestamp, then highest ID, wins. Review affected values before upgrading; source/image downgrade cannot reverse these data changes. Keep the pre-upgrade checkpoint and investigate recovery separately if forward resume is unsafe.

## Evidence and limits

Controlled V3 interruption/resume, isolated checkpoint restore and exact upstream migration fixtures, full verification/audit, native SSH, Sentinel analytics, HTTPS/WebSocket and no-op passed. [Test record](https://github.com/paracosm17/solo-vps/blob/v0.2.3/reviews/2026-10-09-coolify-446-runtime.md). Production full verification/audit preserved all 14 business containers, ENV rows, credentials and proxy; six HTTPS health routes and analytics passed. Fresh encrypted off-host recovery inputs were verified. [Bounded V5 record](https://github.com/paracosm17/solo-vps/blob/v0.2.3/reviews/2026-10-10-coolify-446-production.md). A current-version fresh V4 installation and full application-data disaster recovery are separate gates. Control-plane checkpoints exclude application data.
