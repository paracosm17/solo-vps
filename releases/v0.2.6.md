# Solo VPS v0.2.6 — Traefik 3.7.16 maintenance alpha

This release qualifies **Traefik 3.7.14 to 3.7.16** from the exact v0.2.5 integration baseline. Coolify stays **4.5.0**, Sentinel **1.1.2**. Solo VPS remains an alpha for one Ubuntu 24.04 application VPS.

## Update

Prepare a new v0.2.6 source checkout using the existing external config/inventory. Preserve previous source and fresh verified off-host backups. Older integrations or unrecognized 3.7.14 image identities must first reach the reviewed v0.2.5 baseline; a matching version string alone is insufficient.

Follow [How to update](https://paracosm17.github.io/solo-vps/operations/updates/) ([русский](https://paracosm17.github.io/solo-vps/ru/operations/updates/)). Run `make proxy-upgrade-preflight`, then `PROXY_UPGRADE_CONFIRM=I_HAVE_REVIEWED_THE_PROXY_UPGRADE_PLAN make proxy-upgrade`. Finish with verify/audit, HTTPS/WebSocket and application health checks. Proxy recreation briefly interrupts ingress. No Coolify/database migration, application deployment or OS reboot is required to apply this proxy release.

Preflight stages private helpers/manifest. Upgrade retains native configuration, certificates and a digest-pinned previous image/checkpoint; use the documented same-manifest resume/rollback path on failure. Rollback does not restore arbitrary proxy files or undo concurrent edits. Registry access is still required by native proxy startup.

## Compatibility

Reviewed official [3.7.15](https://github.com/traefik/traefik/releases/tag/v3.7.15), [3.7.16](https://github.com/traefik/traefik/releases/tag/v3.7.16) notes and the [migration guide](https://doc.traefik.io/traefik/v3.7/migrate/v3/). These patches include security fixes. CONNECT requests are now rejected before routing with 501 for all HTTP versions and omitted from access logs. Kubernetes-specific changes do not apply to the maintained Docker topology. Native Coolify 4.5 proxy restart can start its internal error-pages helper; it has no published host port and mounts only the error-pages directory read-only.

Host package maintenance remains separate: Solo VPS already configures Ubuntu security updates and intentionally disables automatic reboot. Keep Coolify's independent host-auto-update switch off. The EN/RU maintenance runbook explains held packages and dependency simulation; no firmware installation, package removal or reboot happens automatically when installing this source release.

## Evidence and limits

Controlled V3 tests cover checkpointed save interruption, resume, digest-pinned rollback, re-upgrade/no-op, full verification/audit, unchanged non-proxy workloads, preserved ACME material and TLS WebSocket. HTTP/1.1 and HTTP/2 CONNECT probes returned 501. A complete encrypted checkpoint with the previous image passed off-host authenticated decryption and transaction-file hash checks. See [test evidence](https://github.com/paracosm17/solo-vps/blob/v0.2.6/reviews/2026-10-25-traefik-3716-runtime.md).

Firmware/reboot maintenance was separately authorized and tested before production; see [host evidence](https://github.com/paracosm17/solo-vps/blob/v0.2.6/reviews/2026-10-25-host-maintenance.md). Fresh installation/V4 and full VPS/application-data recovery remain separate gates. Image inspection/upgrade qualification here is Linux amd64; this release does not broaden architecture support.

Production normal upgrade, full verify/audit and no-op also passed. Original workloads/ENV, ACME material and HTTPS baseline were preserved; the existing development-route 404/503 responses are disclosed rather than reported healthy. WebSocket/Sentinel checks passed, and the complete recovery checkpoint passed authenticated off-host verification. See [bounded V5 evidence](https://github.com/paracosm17/solo-vps/blob/v0.2.6/reviews/2026-10-25-traefik-3716-production.md).
