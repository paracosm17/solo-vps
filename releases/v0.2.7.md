# Solo VPS v0.2.7 — Coolify 4.7.3, Sentinel 1.1.5

This alpha maintenance release adds the reviewed and production-tested Coolify **4.6.0 → 4.7.3** transition, with official pinned artifacts and the already deployed Sentinel **1.1.5**. Traefik **3.7.16** remains unchanged. It also includes the separately production-tested **4.5.3 → 4.6.0** compatibility step.

## Compatibility and how to upgrade

- **Already on Coolify 4.7.3:** no further Coolify upgrade is required. Prepare a tagged v0.2.7 Solo VPS source checkout, preserve the previous checkout, and run `make verify-coolify`, `make verify` and `make audit`.
- **On Coolify 4.6.0:** after verifying backups and running the exact-tag checkout's `make coolify-upgrade-preflight`, run the explicitly guarded `COOLIFY_UPGRADE_CONFIRM=I_HAVE_REVIEWED_THE_COOLIFY_UPGRADE_PLAN make coolify-upgrade`, then the three post-upgrade checks. The managed installation is forward-migrated; a Docker image downgrade is **not** a database rollback.
- **On 4.5.3 or earlier:** follow the earlier Solo VPS release transition to **4.6.0** first. The v0.2.7 manifest does **not** authorize a direct 4.5.3 → 4.7.3 jump.
- See the [EN maintenance guide](docs/operations/updates.md) and [RU maintenance guide](docs/operations/updates.ru.md). Source updates must retain existing SOPS/controller data outside Git.

## Breaking changes from Coolify 4.7.0

- Queued **webhook** deployments are cancelled when superseded by newer pushes, by default. To process all queued webhook builds, opt out per application **after upgrading but before resuming webhook pushes**. API-triggered deployments do not enable this cancellation by default.
- Team/server/resource API authorization is tighter. Existing deployment automation must have the required resource permissions; investigate `403` before broadening tokens.
- Resend sender fields migrate to `resend_from_address` / `resend_from_name`; SSH host-key pinning requires real key-change verification; persistent scheduled-job failures can disable jobs after repeated failures.
- Coolify 4.7.1–4.7.3 include scanner, permissions and backup-administration fixes. Vulnerability scanning is optional and is **not** switched on by this release.

## Runtime and validation

- Exact release artifacts were verified by SHA-256. The official Sentinel 1.1.5 multi-platform index digest and amd64 image config digest are both pinned, so Docker containerd/classic stores pass **only** known image identities.
- On the one maintained production VPS, the operator completed **4.6.0 → 4.7.3** using the guarded lifecycle. Upgrade: `ok=139 changed=9 failed=0`; `make verify-coolify`: `ok=56 failed=0`; `make verify`: `ok=163 failed=0`; `make audit`: `ok=96 failed=0`.
- Coolify 4.7.3, Sentinel 1.1.5 and Traefik 3.7.16 were healthy; control-plane health/realtime/terminal returned HTTP 200, proxy/management-port boundaries were preserved, all **17/17** containers were running, and the upgrade marker was cleared.
- A new age-encrypted control-plane backup was copied outside the VPS with SHA-256 and authenticated decryption/reading verified. See [bounded 4.7.3 production evidence](reviews/2026-11-10-coolify-473-production.md) and the separate [4.6.0 predecessor evidence](reviews/2026-11-04-coolify-460-production.md).

## Evidence boundaries

This is **bounded V5** on an existing production host, **not** a full recovery or fresh-install qualification for Coolify 4.7.3. The owner affirmed separate application backups; no independent application database/volume restore, application-specific HTTPS/business smoke, API deployment proof, disposable V3, UI Sentinel In Sync assertion or configured off-site restic repository was demonstrated by the supplied 4.7.3 logs. Existing host and prior-release evidence remains separate; no missing test is presented as PASS.
