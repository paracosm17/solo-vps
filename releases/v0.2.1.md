# Solo VPS v0.2.1 — Coolify and Traefik maintenance alpha

This patch reviews Coolify 4.4.0 → 4.4.2 and adds an explicit Traefik 3.6.25 → 3.7.14 lifecycle. Versions and image identities remain in `config/coolify-release.yml`. Solo VPS remains an alpha for one Ubuntu 24.04 VPS.

## Update

Prepare a new `v0.2.1` source checkout with your existing external state; keep the previous checkout and fresh verified off-host recovery inputs. Follow the [upgrade guide](https://paracosm17.github.io/solo-vps/upgrades/) ([русский](https://paracosm17.github.io/solo-vps/ru/upgrades/)). Installations still on 0.1.0 must first complete the 0.2.0 transition.

Run Coolify preflight/upgrade first, then `make proxy-upgrade-preflight` and the explicit confirmed `make proxy-upgrade`. Finish with verify/audit, HTTPS application checks and Sentinel analytics delivery. Ordinary host/proxy reconciliation does not update Traefik. Deployments should be idle during the Coolify transition; proxy recreation briefly interrupts requests.

## Changes and evidence

- Coolify 4.4.2 keeps embedded Reverb and the existing checksummed installation artifacts; release-note review includes backup notifications, traffic IP mode and patch fixes.
- Traefik target is pinned by exact version and digest. Upgrade changes only the image scalar through native Coolify actions, with source identity/network/port checks, a private checkpoint and explicit forward resume.
- Proxy rollback restores saved configuration and an immutable previous image; it requires registry access, retains current certificates and leaves the full files archive for reviewed manual recovery.
- Dark documentation command-field labels and controls are readable. Same-image native YAML formatting no longer causes a redundant restart.
- Controlled V3 tests passed Coolify interruption/resume, actual isolated checkpoint database restore, Traefik interruption/resume and rollback/re-upgrade, native analytics toggling/restart, HTTPS, Reverb TLS WebSocket and native SSH backend, full verification/audit and no-op rerun. This is an existing-host patch replay, not a fresh V4 installation.

## Limits

Coolify schema recovery requires a database/configuration recovery procedure; reverting source or an image alone does not undo migrations. Application data is outside control/proxy checkpoints and needs its own backups. Native proxy recovery is online only. Optional integrations, exact-revision new-user installation, external IPv6 packet evidence and reliability guarantees remain separate checks.
