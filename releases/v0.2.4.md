# Solo VPS v0.2.4 — encrypted Coolify backups alpha

Create a Coolify control-plane backup directly on the VPS with `make coolify-backup-local`, or download and authenticate one on a Linux/WSL workstation with `make coolify-backup-export`. Solo VPS remains an alpha for one Ubuntu 24.04 application VPS.

## Update and use

Prepare a new `v0.2.4` checkout using your existing external configuration and inventory; preserve the previous checkout. Follow [How to update](https://paracosm17.github.io/solo-vps/operations/updates/). For installations already on v0.2.3, this is a source update only: Coolify **4.4.6**, Traefik **3.7.14** and Sentinel **1.0.2** remain unchanged. Do not run a platform upgrade for this optional feature.

On the VPS, run the one-time `make coolify-backup-local-prepare SOPS_AGE_RECIPIENT=age1YOUR_PUBLIC_RECIPIENT` as the existing administrator, using the public recipient of your workstation's age identity. Then run `make coolify-backup-local` without parameters. It prints a unique `.tar.gz.age` path and ciphertext SHA256; default files are outside the checkout under `~/.local/share/solo-vps/backups/` with mode 0600. The private identity stays off the VPS. Existing public policy is preserved; a conflicting recipient is refused.

See [Coolify backups](https://paracosm17.github.io/solo-vps/operations/coolify-backups/) ([русский](https://paracosm17.github.io/solo-vps/ru/operations/coolify-backups/)) for workstation export, transfer, verification and an optional cron example. No schedule or deletion policy is enabled automatically. Native Windows Make is unsupported; use WSL or remote SSH to the Linux command.

## Evidence and limits

Fourteen focused source tests, independent security/recovery review and controlled V3 test-VPS evidence cover distinct parameterless backups, minimal cron-like environment, shared-lock rejection, private output permissions, off-host authenticated decryption/checksums and an isolated database restore. All seven running test containers retained their identities, images, start times and health. See [the local backup record](https://github.com/paracosm17/solo-vps/blob/v0.2.4/reviews/2026-10-10-local-coolify-backup-runtime.md) and [workstation export evidence](https://github.com/paracosm17/solo-vps/blob/v0.2.4/reviews/2026-10-10-coolify-backup-export-runtime.md).

These archives contain the Coolify control plane, not application databases/volumes or a full VPS image. Database and configuration capture is not atomic: pause deployments, upgrades and settings changes. Protected temporary plaintext staging exists during collection; interruption can require manual cleanup. Local creation validates content before encryption but cannot authenticate decryption without the separately held private identity. Transfer copies off the VPS and verify decryption there. Full disaster recovery, new clean-host installation and production replay of this optional feature are separate evidence gates.
