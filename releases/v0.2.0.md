# Solo VPS v0.2.0 — Coolify 4.4.0 and maintenance alpha

This release supports the reviewed Coolify 4.3.21 → 4.4.0 transition, one read/write/deploy API token, local documentation values and read-only update discovery. Solo VPS remains an alpha for one Ubuntu 24.04 VPS.

## Install or update

New installations: follow the [Quick Start](https://paracosm17.github.io/solo-vps/quick-start/) ([русский](https://paracosm17.github.io/solo-vps/ru/quick-start/)). Use this source checkout in the clone step:

```bash
git clone --branch v0.2.0 --depth 1 https://github.com/paracosm17/solo-vps.git solo-vps
cd solo-vps
```

Existing installations: prepare a new checkout of `v0.2.0`, preserve the previous source and existing external state, and follow the [upgrade guide](https://paracosm17.github.io/solo-vps/upgrades/) ([русский](https://paracosm17.github.io/solo-vps/ru/upgrades/)). Keep working administrator SSH and provider recovery access. Run `make firewall` and `make verify-firewall` before the Coolify preflight. Prepare verified backups of Coolify and application data, and pause deployments/settings changes for the transition.

Use the Solo VPS upgrade commands. The Coolify Update button/automatic upgrade bypass the reviewed artifact hashes, private checkpoint and transaction-bound resume. Returning to old source does not undo migrations; image-only downgrade is not a recovery procedure.

## Changes

- `config/coolify-release.yml` is the shared reviewed release definition: versions, registries, realtime topology, artifact hashes, Sentinel identities and evidence. Compatible future patch qualification no longer requires changing versioned executable filenames.
- `make updates-check` reads available Solo VPS/Coolify releases; `make updates-plan` works offline. Discovery never installs an upstream version.
- Coolify 4.4.0 uses embedded Reverb. Upgrade preserves secrets/SSH identities and retires only the owned legacy realtime container. Native Sentinel 1.0.2 is verified against the reviewed identity.
- Native saved proxy configuration preserves public TCP 80/443. A bounded IPv4/IPv6 firewall guard runs before Docker restores workloads and blocks forbidden TCP 8080/UDP 443 ingress without moving shared forwarding rules.
- The reference CI and deployment helpers use one `COOLIFY_API_TOKEN` with `read`, `write`, `deploy`. Tokens are team-scoped, not restricted to one application.
- Documentation can substitute locally entered server/user values into commands. Values stay in the browser tab; no server transmission or persistence is required. Input prompts work in Bash/zsh, and VPS-only host-key commands are identified.
- Standalone firewall network facts, effective systemd guard checks and UTC timezone alias verification are corrected.

## Validation

Controlled disposable-VPS integration covered exact-origin upgrade, interruption/forward resume, checkpoint database restore, credential preservation, immutable application deployment/failed-image rollback, native proxy restart, actual websocket/terminal, verification/audit and reboot.

The owner-reset fresh host reached a working platform/application after fixes and continued installation. Final corrected source passed verification/audit, idempotent platform rerun, native proxy restart, real TCP/UDP DROP counter checks. The replay included two reboots: the first exposed a verifier issue and the corrected source passed the second. This is **V3 controlled integration with corrected-source resume**. The old independent V4 clean-user walkthrough applies to the original 0.1.0 source, not the changed installation/firewall route.

The maintained production VPS then upgraded successfully: full verify/audit and the upgrade rerun reported `changed=0`, the 14 business containers retained their image/mounts/start times, production bot HTTPS health passed, Sentinel was in sync, and native origin HTTPS terminal/SSH PTY plus Reverb checks passed. Verified encrypted backups remain offhost. See [the bounded production record](https://github.com/paracosm17/solo-vps/blob/v0.2.0/reviews/2026-10-07-coolify-440-production.md). This point-in-time result does not guarantee production reliability. Local/source checks and hosted CI are separate gates; backup archive readability is not a full restore rehearsal.

## Limits

- No high availability, production reliability, notification-latency or retention-duration guarantee.
- An uninterrupted exact-revision new-user browser walkthrough and external IPv6 packet proof remain separate checks.
- Optional B2/restic, backup UI/API and monitoring keep their own evidence; their 4.4.0 qualification is not implied by the core upgrade.
- The checkpoint contains Coolify database/configuration/SSH identity, excludes application data and cannot survive VPS loss. Keep verified copies outside the VPS.
- Container-image rollback excludes database schema, data changes and external side effects.
- Compatibility may change in later 0.x releases.
