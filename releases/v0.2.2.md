# Solo VPS v0.2.2 — Coolify 4.4.3 maintenance alpha

This patch qualifies **Coolify 4.4.2 → 4.4.3**. Traefik stays on reviewed **3.7.14**; an installation already updated to 0.2.1 needs no proxy upgrade. Solo VPS remains an alpha for one Ubuntu 24.04 application VPS.

## Update

Prepare a new `v0.2.2` checkout with the existing external config, inventory and keys. Keep previous source and fresh verified off-host backups. Follow [How to update](https://paracosm17.github.io/solo-vps/operations/updates/) ([русский](https://paracosm17.github.io/solo-vps/ru/operations/updates/)).

Run `make coolify-upgrade-preflight` with the exact configured Sentinel HTTPS URL, then the explicitly confirmed `make coolify-upgrade`. Finish with `make verify`, `make audit`, application HTTPS checks and Sentinel delivery. Pause deployments/settings changes during the transition. Older installations must follow intermediate release notes until Coolify 4.4.2 is installed.

## Changes

- Coolify 4.4.3 fixes terminal container selection, runtime log filters, nested API labels, duplicate DNS/file-sync jobs and other upstream issues. All official notes and the exact tag comparison were reviewed. Installation artifacts, embedded Reverb and Sentinel 1.0.2 remain unchanged.
- The built-in server's default `localhost` name becomes configured `server.hostname`. Existing custom names are preserved. UUID, SSH address/user/key, destinations and application associations stay unchanged. Daily naming remains Coolify-owned.
- EN/RU installation versions come from the shared manifest. Obsolete history was removed from user guides. ADRs and maintainer decision pages remain in the repository, outside the published site/search index.
- The delivery reference stays GitHub Actions → GHCR immutable digest → Coolify Docker Image, keeping builds off the VPS. Git-source/App and multi-container Compose alternatives are explained without migrating running applications.
