# Solo VPS v0.1.0 — first public alpha

Solo VPS configures one Ubuntu 24.04 VPS with an administrator account, hardened SSH, firewall, security updates, Docker and Coolify. The English and Russian guides continue through a first application and automatic deployment from GitHub Actions via GHCR.

## Start here

- [Quick Start](https://paracosm17.github.io/solo-vps/quick-start/)
- [Быстрый старт на русском](https://paracosm17.github.io/solo-vps/ru/quick-start/)

Minimum supported host: Ubuntu 24.04 LTS, 2 vCPU, 2 GiB RAM and 30 GiB free disk. You need a domain, root SSH access and provider recovery-console access. Workstation commands are documented for Windows PowerShell and Linux/WSL.

Follow the Quick Start. At **step 2**, on the VPS as root, replace its clone block with this release-specific block:

```bash
git clone --branch v0.1.0 --depth 1 https://github.com/paracosm17/solo-vps.git solo-vps
cd solo-vps
```

Continue with step 3; no manual commit hash is needed.

## Included

- Host configuration, SSH hardening, Docker and verification/audit commands.
- Coolify `4.3.21`, HTTPS onboarding and loopback-only management ports.
- GitHub Actions application template: tests, GHCR image publishing, immutable image deployment and bounded failed-image rollback.
- Instructions and tooling for optional PostgreSQL backups, restic off-site copies, recovery, retained logs, VPS metrics and external outage monitoring.
- A tagged-checkout source update procedure that keeps installation state outside the source tree.

## What was tested

The owner independently completed the public core guide on a clean Ubuntu 24.04 VPS at `0fdba7f`, including a working application and automatic deployment. Supplied logs show successful host verification, security audit and a second platform run with `changed=0`. Release preparation preserves that operational source.

Separate controlled VPS exercises covered the Coolify `4.1.2` → `4.3.21` upgrade/resume, lost-VPS recovery, PostgreSQL and restic restore, retained logs, metrics and real whole-host DOWN/UP notifications. These are integration results, not a production reliability guarantee. See [the core evidence record](https://github.com/paracosm17/solo-vps/blob/v0.1.0/reviews/2026-09-28-clean-user-replay.md).

## Alpha limits

- Use a test VPS first. There is no high availability or production guarantee.
- The supported topology is one VPS. Multi-node operation and automated team access management are outside this release.
- Optional backups and monitoring need your own external accounts and credentials.
- Image rollback does not reverse database migrations, data changes or external side effects.
- Coolify `4.3.21` database backup scheduling uses the documented UI path. The API adoption helper refuses the incomplete schedule response rather than guessing the S3 storage binding.
- No fixed notification-delivery time or log-retention duration is promised.
- Compatibility may change in later `0.x` releases. Review the upgrade guide and release notes before updating.
