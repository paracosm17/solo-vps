# Резервная диагностика хоста: статус и логи

Используйте эти команды, когда Coolify или обычный observability-интерфейс недоступен и нужен ограниченный read-only взгляд на хост.

## Быстрый статус хоста

**Где: VPS/контроллер под управляемым администратором**

```bash
make ops-status
```

Команда выводит компактное резюме по хосту и контейнерам, не меняя desired state. Обычный ежедневный интерфейс остаётся прежним: GitHub Actions для CI и Coolify для деплоев, runtime-логов, секретов и терминалов.

## Последние логи одного контейнера

Явно выберите контейнер:

```bash
make ops-logs CONTAINER=<container> TAIL=100
```

Для диагностики используйте ограниченный tail. Этот путь **read-only** и является **fallback**, а не основным интерфейсом ежедневной работы с приложением. Всегда **просматривайте вывод перед тем, как им делиться**: application logs могут содержать чувствительные данные.

## Если информации с хоста недостаточно

Запустите более широкие read-only проверки:

```bash
make doctor
make verify
make audit
```

После этого вернитесь в интерфейс, который отвечает за соответствующую область:

- GitHub Actions — детали ошибок CI;
- Coolify — состояние deployment/application runtime;
- Grafana — историческая observability, если она включена.
