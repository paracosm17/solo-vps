# Обновление Solo VPS, Coolify и Traefik

Используйте эту страницу, когда установка уже работает и появился новый релиз Solo VPS или уведомление об обновлении Coolify/Traefik.

Все команды выполняйте **в Bash/WSL из каталога Solo VPS на том же контроллере, с которого настраивали сервер**. Если контроллер работает на самом VPS, войдите под существующим администратором и начните из `~/solo-vps`. Сохраняйте прежние config, inventory и ключи; повторная установка сервера не нужна.

## Что именно обновляется

В Coolify выбирайте существующий локальный сервер по его текущему имени. При новой установке это `server.hostname`; пользовательские имена сохраняются. Во время preflight прежнее стандартное имя ещё может отображаться: оно обновится в процессе обновления.

| Компонент | Что меняется | Как обновить |
| --- | --- | --- |
| Solo VPS | Исходники автоматизации и проверенные версии компонентов | Подготовить новый checkout опубликованного тега |
| Coolify | Панель, её база и служебные контейнеры | Из новых исходников выполнить `coolify-upgrade-preflight`, затем `coolify-upgrade` |
| Traefik | Образ reverse proxy | Выполнить `proxy-upgrade-preflight`, затем `proxy-upgrade` |

Обновление исходников само по себе не меняет работающие контейнеры. Когда нужно обновить оба компонента, порядок такой: **Solo VPS → Coolify → Traefik → проверка**. Выполняйте только переходы, указанные в release notes выбранного Solo VPS.

## 1. Узнайте, есть ли проверенное обновление

Из текущего каталога проекта:

```bash
make updates-check
make updates-plan
```

Первая команда проверяет GitHub Releases **Solo VPS и Coolify**; вторая показывает локальный план без сети. Отдельного поиска upstream-релизов Traefik эта команда пока не делает: его проверенную версию смотрите в release notes Solo VPS и `config/coolify-release.yml`.

Уведомление в Coolify сообщает о релизе upstream. Для установки через Solo VPS сначала нужен опубликованный релиз Solo VPS, в котором проверен этот переход. **Если такого релиза ещё нет, оставьте работающую версию и дождитесь проверки совместимости.** Изменение номера в конфиге не заменяет её.

Установленные исходники продолжают использовать проверенную версию даже после выхода нового релиза upstream. Выберите опубликованный Solo VPS, чьи release notes поддерживают переход с вашей установки. Если обновлён только Traefik, новая версия Solo VPS может сохранять текущую версию Coolify.

## 2. Выберите релиз и подготовьте восстановление

Откройте [GitHub Releases Solo VPS](https://github.com/paracosm17/solo-vps/releases). Прочитайте, какие текущие версии поддерживаются, какие компоненты меняются и какие действия нужны. При несовпадении исходной версии следуйте указанным промежуточным релизам.

До изменения runtime:

- подготовьте и проверьте свежие копии базы/конфигурации Coolify, файлов/образа proxy и данных приложений; держите зашифрованную копию вне VPS;
- убедитесь, что работают SSH администратора и console/rescue провайдера;
- дождитесь завершения деплоев; на время перехода приостановите новые деплои и изменения настроек;
- проверьте текущий `/healthz` приложений и сохраните старый каталог исходников.

См. [внешние резервные копии](offsite-backups.md), [копии PostgreSQL](postgresql-backups.md) и [границы восстановления](../upgrades.md#rollback-recovery). Автоматические локальные checkpoints обновления дополняют эти копии и не переживут потерю VPS.

## 3. Подготовьте новые исходники Solo VPS

В **старом** каталоге проекта сохраните вывод `make paths`, затем введите точный опубликованный тег из Releases:

```bash
make paths
printf '%s' 'Тег Solo VPS из GitHub Releases (v0.x.y): '; read -r RELEASE_VERSION
make source-update-prepare RELEASE_VERSION="$RELEASE_VERSION" && cd "../solo-vps-$RELEASE_VERSION"
```

После успешной подготовки, из нового каталога:

```bash
make setup
make paths
make validate
make doctor
make updates-plan
```

Продолжайте только после успешного завершения команд. Пути config/inventory в новом и старом каталоге должны совпадать. Команда подготовки не перезаписывает старый checkout и не обновляет VPS. Локальные изменения в старом каталоге или уже существующий целевой каталог нужно сначала проверить отдельно.

Работайте дальше из нового каталога. Если контроллер находится на VPS, сохраните прежний `~/solo-vps` отдельно и разместите новый checkout по этому стандартному пути, как описано в [подробной процедуре](../upgrades.md#vps).

## 4. Обновите Coolify, если это требуется релизом

Сверьте установленную версию в панели с текущей целью из `make updates-plan` и release notes **нового checkout**. Если они совпадают, переходите к следующему требуемому компоненту.

Если нужен поддерживаемый переход, скопируйте точный HTTPS URL из **Servers → `server.hostname` → Sentinel → Configuration → Coolify URL**, включая завершающий `/`, если он задан. Sentinel должен показывать **In Sync**.

```bash
printf '%s' 'Точный Coolify URL из настроек Sentinel: '; read -r COOLIFY_SENTINEL_URL
export COOLIFY_SENTINEL_URL
make coolify-upgrade-preflight
```

После успешного preflight и проверки копий:

```bash
COOLIFY_UPGRADE_CONFIRM=I_HAVE_REVIEWED_THE_COOLIFY_UPGRADE_PLAN make coolify-upgrade
make verify-coolify
```

Команда сохранит локальный checkpoint и выполнит проверенный переход. При ошибке остановитесь и прочитайте [порядок продолжения](../upgrades.md#interrupted-upgrade).

Перед подтверждением прочитайте о миграциях данных в примечаниях к выбранному релизу Solo VPS. Даже патчи Coolify могут удалять дубли переменных окружения или нормализовать адреса. Возврат старых исходников/образа не отменяет эти изменения; сохраните копию базы до обновления и приостановите правки настроек/ENV до завершения проверки.

Для этого пути используйте команды Solo VPS. Кнопка **Update** в Coolify обходит его checkpoint, проверенные артефакты и transaction/resume; такой переход не считается проверенным этой интеграцией.

## 5. Обновите Traefik, если это требуется релизом

Целевой образ задан в `config/coolify-release.yml` нового checkout. Preflight проверяет допустимый исходный образ, состояние proxy, сети и публичные порты:

```bash
make proxy-upgrade-preflight
```

После успешной проверки:

```bash
PROXY_UPGRADE_CONFIRM=I_HAVE_REVIEWED_THE_PROXY_UPGRADE_PLAN make proxy-upgrade
```

Будет сохранён checkpoint и заменён только образ через штатные действия Coolify. Настройки аналитики, сертификаты и конфигурация маршрутов сохраняются. Пересоздание proxy ненадолго прерывает входящие запросы. Обновление выполняется отдельной командой; обычная настройка портов не меняет его версию.

Если исходный образ не входит в проверенный набор, остановитесь. Для прерванной операции и отката используйте [процедуру Traefik](../upgrades.md#traefik-reverse-proxy).

## 6. Проверьте результат

```bash
make verify
make audit
```

Откройте панель Coolify и реальные приложения, проверьте их `/healthz`, Sentinel **In Sync** и поступление аналитики, если она включена. Сохраните новые checkpoints вне VPS. Старые исходники и копии оставьте до подтверждения результата и окончания выбранного периода хранения.

Обновление завершено, когда версии соответствуют выбранному релизу, проверки проходят и приложения работают. Возврат старого каталога исходников не отменяет миграции Coolify. Подробности по Docker, Ubuntu и восстановлению после неудачного перехода — в [справочнике обновлений](../upgrades.md).
