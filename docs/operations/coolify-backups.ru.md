# Копии Coolify: локальный архив или экспорт на рабочую машину

Команды копируют **управляющую часть Coolify**: PostgreSQL dump, конфигурацию исходников, серверные SSH-ключи, конфигурацию/сертификаты proxy, конфиг/inventory оператора и метаданные платформы. Внутренний manifest содержит SHA256 файлов.

**Базы и тома приложений копируются отдельно.** Сохраняйте [копии PostgreSQL](postgresql-backups.md) и [внешние копии данных](offsite-backups.md). Исключены образы Docker, access logs, старые checkpoints и identities рабочей машины. Приостановите деплои/обновления/правки настроек: база и файлы снимаются не атомарно. Автоматического полного восстановления VPS или отката базы у этих архивов нет.

## Выберите место создания файла

| Команда | Где запускается | Результат |
| --- | --- | --- |
| `make coolify-backup-local` | На VPS, от существующего администратора | Локальный `.tar.gz.age`; без скачивания и приватного identity |
| `make coolify-backup-export` | На рабочей машине Linux/WSL | Скачанный `.tar.gz.age` с локальной проверкой расшифровки |

Обе команды используют общую неблокирующую capture-блокировку, проверяют dump, содержимое архива и коды завершения, публикуют новый файл атомарно. Старые файлы не перезаписываются и не удаляются. Платформа должна быть здорова, без незавершённой установки/обновления.

## Локальная копия на VPS

### Подготовить один раз

Приватный age identity остаётся на рабочей машине. Возьмите его **публичный recipient** (`age1...`) из существующего публичного файла SOPS recipient или вывода настройки age на рабочей машине. Не создавайте новый identity на VPS и не копируйте туда `age-key.txt`.

На VPS, от существующего администратора, из `~/solo-vps`:

```bash
make coolify-backup-local-prepare SOPS_AGE_RECIPIENT=age1YOUR_PUBLIC_RECIPIENT
```

Команда использует существующие публичные policy/recipient SOPS и устанавливает/проверяет закреплённые age-инструменты. S3 и restic не нужны. Другой существующий recipient не перезаписывается: выясните, какой ключ используется, прежде чем применять документированный порядок ротации. Для нестандартных путей укажите тот же `SOLO_VPS_DATA_DIR`, что использует установленный контроллер.

### Создать

```bash
make coolify-backup-local
```

Команда напечатает путь и SHA256 шифротекста. По умолчанию файл находится во внешнем data root текущего администратора, `~/.local/share/solo-vps/backups/`, имеет уникальное имя с временем и права `0600`. Через sudo без запроса пароля работает только сборщик; сам Make запускайте без `sudo`.

На сервере проверяются открытый dump/архив и поток **до шифрования**. Публичного recipient недостаточно для расшифровки результата. После переноса вне VPS проверьте расшифровку своим отдельно хранимым приватным identity; восстановление dump в отдельную БД даёт дополнительное подтверждение пригодности копии. Отдельно сохраняйте identity: при его потере бэкапы прочитать невозможно.

Для конкретного нового имени задайте `COOLIFY_BACKUP_OUTPUT=/protected/path/backup.tar.gz.age` вне каталога исходников.

### Windows без WSL

Make/crypto helper рассчитан на Linux; это не нативная команда PowerShell. Из Windows PowerShell с OpenSSH, существующим ключом администратора и проверенным ключом сервера можно выполнить **команду на VPS удалённо**, затем забрать шифротекст обычным SCP:

```powershell
ssh ops@203.0.113.10 'cd ~/solo-vps && make coolify-backup-local'
scp 'ops@203.0.113.10:/home/ops/.local/share/solo-vps/backups/EXACT_FILE.tar.gz.age' "$env:USERPROFILE\solo-vps-backups\"
```

Укажите точное напечатанное имя и существующий локальный каталог назначения. Приватный age identity остаётся в Windows. Это нативный транспорт SSH/SCP к Linux-команде, а не нативный запуск Make или экспортера в Windows.

### Опциональное расписание

После первой успешной копии и проверки вне VPS администратор может добавить пример в **свой** `crontab -e` (каждые шесть часов):

```cron
0 */6 * * * /usr/bin/make -C /home/ops/solo-vps coolify-backup-local >> /home/ops/.local/share/solo-vps/backups/cron.log 2>&1
```

Измените пути и интервал. Автоматически расписание не включается. Локальные файлы занимают диск и не переживут потерю VPS; организуйте внешнее копирование и собственный срок хранения. Команда никогда не удаляет старые бэкапы. При занятой блокировке повторный сбор завершится ошибкой вместо запуска второго dump.

## Экспорт на рабочую машину Linux/WSL

Используйте существующий SSH-ключ администратора, проверенный `known_hosts`, sudo без запроса пароля и локальный identity в `~/.config/solo-vps/age-key.txt` (либо `AGE_KEY_FILE`). Один раз установите закреплённые crypto tools через `make secrets-tools`. Временный сборщик передаётся по SSH; устанавливать исходники этой функции на VPS не нужно.

С существующим single-host inventory:

```bash
make coolify-backup-export
```

Если контроллер работает на самом VPS, укажите адрес подключения вместо ведения второго inventory:

```bash
make coolify-backup-export BACKUP_VPS_HOST=203.0.113.10 BACKUP_VPS_USER=ops
```

Стандартные удалённые пути: `/home/<admin>/solo-vps` и `/home/<admin>/.local/share/solo-vps`. Для нестандартных задайте `COOLIFY_BACKUP_REMOTE_SOURCE` и `COOLIFY_BACKUP_REMOTE_DATA_DIR`. Чтение inventory допускает один прямой host с опциональным портом/путём приватного ключа, без наследуемых/специальных настроек подключения; явно ключ задаётся через `BACKUP_SSH_IDENTITY_FILE`.

Чтобы сохранить прямо в Windows из WSL:

```bash
make coolify-backup-export \
  BACKUP_VPS_HOST=203.0.113.10 BACKUP_VPS_USER=ops \
  AGE_KEY_FILE=/mnt/c/Users/YOUR_USER/.config/solo-vps/age-key.txt \
  COOLIFY_BACKUP_OUTPUT=/mnt/c/Users/YOUR_USER/solo-vps-backups/pre-update.tar.gz.age
```

**Файл уже скачан.** Этот режим проверяет аутентифицированную расшифровку, SHA256 всего потока и каждый файл manifest локально до публикации итогового имени. Открытые архивы не записываются на диск рабочей машины.

## Ошибки и границы восстановления

Штатные ошибки очищают только приватный staging и `.partial` этого запуска; прежние копии/checkpoints сохраняются. Убитый процесс или обрыв могут оставить временные файлы: проверьте принадлежность перед удалением и повторите с новым именем. Возобновления потока нет. Общая capture-блокировка не заменяет приостановку деплоев/правок настроек. См. [границы восстановления](../upgrades.md#rollback-recovery): валидный архив сам по себе не означает проверенное полное восстановление.
