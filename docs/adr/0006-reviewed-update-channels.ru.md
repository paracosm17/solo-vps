# ADR-0006: Проверка версий, подготовка исходников и обновление платформы

Status: Accepted
Date: 2026-10-07

## Контекст

Coolify выходит чаще Solo VPS. Alpha 0.1.0 использовала Coolify 4.3.21; в 4.4.0 realtime перенесён внутрь основного контейнера. Это требует изменений локальных портов и проверок. Установка любой обнаруженной upstream-версии обходит такую проверку совместимости.

## Решение

Источник целевой версии, исходной версии, image и SHA256 артефактов — файл с постоянным именем `config/coolify-release.yml`. Lifecycle policy остаётся проверяемым кратким контрактом. Команды испытания используют тот же manifest без копий pin. Имена исполняемых файлов и Make-команд не содержат версию; исторические доказательства могут её содержать.

Для совместимого upstream-релиза версии компонентов и хеши артефактов меняются в этом одном файле. Ссылки на образы и загрузки, планы, проверки восстановления и текущие значения документации вычисляются из него. Изменения интеграции требуют кода и тестов. Доказательства привязаны к отпечатку manifest: новая версия не наследует старую проверку. Описательные поля квалификации исключены из идентичности транзакции. Sentinel обновляет Coolify; исходный и целевой образы заданы явно, включая разрешение проверенному целевому агенту обновиться раньше платформы.

`updates-check` читает публичные release metadata и показывает upstream отдельно от проверенной цели и уровня доказательств. `updates-plan` работает без сети. Эти команды ничего не устанавливают. Наличие upstream-релиза не разрешает его установку.

`source-update-prepare` создаёт отдельный checkout выбранного опубликованного точного тега Solo VPS. Настройки остаются вне Git; прежний checkout сохраняется. Новые исходники не запускают Ansible автоматически. Небольшое обновление совместимости может выходить в patch-релизе Solo VPS: новый Coolify patch не требует нового minor-релиза. Отдельный удалённый исполняемый каталог совместимости не вводится.

Обновление Coolify использует явный preflight, приватную локальную копию управляющего состояния, SHA256 артефактов, защищённый маркер транзакции, проверки и forward resume. Resume сравнивает точные строки маркера и идентичность артефактов/override. Существующие секреты сохраняются. Откат версии не отменяет миграции БД. Локальная копия сохраняется; проверка читаемости dump/архива не доказывает восстановление БД.

Кнопка Update в Coolify и скрипты с плавающими артефактами не входят в подтверждённый путь. `AUTOUPDATE=false` сохраняется: upstream-обновление может обойти наши копии/маркеры и перезаписать Compose-политику.

Явный запуск Compose в Coolify не загружает отдельный override proxy. Ansible задаёт TCP-политику через нативные Get/Save actions; жизненным циклом proxy управляет Coolify. Меняется только поле ports, образ и сети проверяются до необходимого нативного перезапуска. Ограниченная защита хоста блокирует входящие TCP 8080/UDP 443 до запуска контейнеров Docker, включая первый старт и перезагрузку. Общие правила firewall и ответы на исходящие запросы сохраняются; IPv4 и IPv6 защищаются отдельно.

## Следствия и испытание

Исходники Solo VPS обновляются, когда нужна новая проверенная интеграция, а Coolify обновляется отдельной явной командой. Старый checkout не умеет проверять произвольные будущие версии. Владельцы сервера и приложения остаются прежними.

Переход `4.3.21 → 4.4.0` на тестовом VPS прошёл проверку V3: прерывание/продолжение, восстановление БД из checkpoint, повторный запуск без изменений, приватность портов, Reverb/terminal, доставка данных Sentinel, прежние Docker и SSH-идентичность, деплой/откат immutable image одним токеном и перезагрузка. См. [результаты проверки](https://github.com/paracosm17/solo-vps/blob/main/reviews/2026-10-07-coolify-440-runtime.md). Чистая установка, production и публикация нового релиза остаются отдельными этапами и действиями владельца.
