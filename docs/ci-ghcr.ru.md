# Справочник CI/CD

Полная настройка находится в [2. Запустите приложение и настройте CI/CD](operations/first-app.md). Там есть создание SSH-ключа, CI-пользователя, токена Coolify, заполнение GitHub и первый автоматический деплой.

Эта страница объясняет устройство workflow и его перенос в существующее приложение.

## Порядок доставки

| Что запущено | Результат |
| --- | --- |
| Pull request | Тесты, линтер, проверка миграций и сборка образа; без публикации и деплоя |
| Первый push в `main`, CD выключен | Тесты, публикация образа в GHCR и проверка его digest |
| Push в `main`, CD включён | Те же проверки, затем деплой через окружение `production` и ограниченный SSH-туннель |

GitHub Actions собирает образ. Coolify скачивает и запускает его на VPS. Workflow разворачивает ровно опубликованный `name@sha256:digest`; тег `latest` не используется. Отдельный runner скачивает этот digest и проверяет `/healthz` до деплоя.

Workflow приложения находится в `templates/github-actions/hello-app-ci.yml`. Файл самого Solo VPS `.github/workflows/repository-ci.yml` проверяет инфраструктурный репозиторий; его проверки и доступы настраиваются отдельно.

## Перенос шаблона в своё приложение

Starter из runbook уже содержит полный комплект. Для существующего приложения используйте соответствие файлов:

```text
templates/github-actions/hello-app-ci.yml -> .github/workflows/app.yml
scripts/coolify_deploy_api.py             -> scripts/coolify_deploy_api.py
scripts/check_release_revision.py        -> scripts/check_release_revision.py
tests/test_release_revision.py           -> tests/test_release_revision.py
scripts/validate_coolify_image_handoff.py -> scripts/validate_coolify_image_handoff.py
templates/github-actions/tests/*          -> tests/
```

Создайте пустые `scripts/__init__.py` и `tests/__init__.py`, если их ещё нет. Скопируйте или адаптируйте `requirements-dev.txt`, `ruff.toml` и принадлежащий приложению `migration_preflight.py` из `examples/hello-app/`. Измените `APP_DIR`, пути и команды тестирования/сборки под своё приложение. Подробности комплекта находятся в `templates/github-actions/README.md`.

Образу нужна содержательная проверка здоровья. До включения CD вручную разверните фиксированный digest и дождитесь `running:healthy`: это предыдущий образ для восстановления. Приватному GHCR-образу также нужен проверенный [доступ Coolify к реестру](https://coolify.io/docs/knowledge-base/docker/registry). Публичному демо он не требуется.

## Параметры деплоя

В runbook последовательно описаны [создание ключа и CI-пользователя](operations/first-app.md#ci-key), затем [окружение GitHub](operations/first-app.md#github-production). Состав настроек:

| Где | Имя | Значение |
| --- | --- | --- |
| Окружение `production`: secret | `SOLO_VPS_DEPLOY_SSH_KEY` | Отдельный приватный CI-ключ без passphrase |
| Окружение `production`: secret | `COOLIFY_API_TOKEN` | Токен текущей команды с `read`, `write`, `deploy` |
| Окружение `production`: variable | `SOLO_VPS_DEPLOY_HOST` | Адрес сервера без пользователя, протокола и порта |
| Окружение `production`: variable | `SOLO_VPS_SSH_KNOWN_HOSTS` | Одна доверенная строка Ed25519-ключа сервера с этим адресом |
| Окружение `production`: variable | `SOLO_VPS_DEPLOY_SSH_FINGERPRINT` | Отпечаток CI-ключа `SHA256:...` |
| Окружение `production`: variable | `COOLIFY_RESOURCE_UUID` | UUID приложения |
| Репозиторий: variable | `SOLO_VPS_DEPLOY_ENABLED` | `true`, после первого здорового деплоя и подготовки доступа |

Серверный пользователь `solo-vps-ci` разрешает только локальный TCP-forward к `127.0.0.1:8000`, без shell, sudo и группы Docker. Ключ сервера получают через доверенную административную сессию; непроверенный `ssh-keyscan` не подтверждает подлинность сервера. Аргументы плана `CI_DEPLOY_*` не сохраняют конфигурацию: `ci_deploy.ssh_public_key_file` должен указывать на публичный ключ на контроллере.

## Миграции базы данных

**Application migration preflight** выполняется после тестов и до публикации образа с правом `contents: read`. Ему не передаются секреты production, деплоя или базы данных.

За миграции отвечает приложение. Проверка preflight не должна менять данные. Предпочитайте обратно совместимые изменения expand/contract. Перед необратимыми изменениями подготовьте свежую резервную копию и проверенный план восстановления либо исправления вперёд. Solo VPS не запускает общие миграции БД за приложения.

## Неудачный или устаревший деплой

Перед обновлением helper требует, чтобы текущий образ имел фиксированный digest и был healthy. Задания деплоя выполняются последовательно. Внутри задания проверяется коммит: если в `main` уже есть более новый, старый деплой пропускается.

После подтверждённого сбоя нового образа helper пытается вернуть и развернуть предыдущий. Даже при успешном восстановлении CI остаётся красным со статусом `DEPLOY_FAILED_ROLLBACK_OK`. Возвращается **образ контейнера**, а не состояние БД или внешних систем.

При таймауте или неизвестном статусе откат не запускается, пока исходный деплой может продолжаться. Перед ручными действиями откройте Coolify Deployments. Если восстановление не удалось, используйте [инструкцию по откату](operations/deployment-rollback.md) и диагностические сведения из CI; токен в них не печатается.

## Границы доступа

- PR не получает production-секреты и не публикует/деплоит образ.
- Публикация в GHCR использует `GITHUB_TOKEN` репозитория; право `packages: write` выдано только этому заданию.
- Сторонние Actions закреплены полными commit ID.
- Задание деплоя использует `cancel-in-progress: false` и строгую проверку SSH-ключа сервера.
- Прямой доступ к портам управления `8000/6001/6002` закрыт извне; CI обращается к 8000 через ограниченный туннель.
- Токену Coolify нужны `read`, `write`, `deploy`. Он действует в текущей команде и истекает согласно выбранному сроку.
- GitHub хранит секреты деплоя, Coolify — секреты работающего приложения. SOPS + age используется для секретов инфраструктуры и восстановления.

В правилах защиты ветки требуйте проверки, которые создаёт workflow вашего приложения: например, тесты и сборку PR-образа. Проверки самого Solo VPS, такие как `fast-source`, не нужно требовать в приложении, где они не запускаются.

## Где смотреть результат

| Задача | Место |
| --- | --- |
| Проверить тесты, сборку или задание деплоя | GitHub → репозиторий → Actions |
| Найти опубликованный digest | Summary запуска Actions или пакет GHCR |
| Посмотреть историю деплоев и ошибки старта | Coolify → приложение → Deployments |
| Посмотреть вывод приложения | Coolify → приложение → Logs |
| Изменить runtime ENV | Coolify → приложение → Environment Variables |

Дополнительные настройки описаны в [переменных и секретах приложения](operations/application-config-and-secrets.md), обзор интерфейса — в [ежедневной работе](operations/operator-ui.md).
